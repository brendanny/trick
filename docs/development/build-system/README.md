# CMake migration build contract (A1)

**Current implementation:** [A4 dependency preflight](dependencies.md), above
[A3 utility archives](utilities.md) and [A2 bootstrap](bootstrap.md).

This directory defines the migration from Trick's Autoconf and handwritten
framework Make build to a replacement CMake implementation. It is the first
reviewable layer, A1. It changes documentation only; it does not make the
existing CMake implementation usable.

The source baseline is [nasa/trick PR 2190](https://github.com/nasa/trick/pull/2190)
at `62d6091db51c25e73874f62f670fdcb3772b6220`. Source observations are pinned
to that revision. Reconcile this inventory when the prerequisite lands or
changes. The separate draft CMake implementation is not a design input.

## Agreed constraints

| Constraint | Contract |
| --- | --- |
| CMake | Minimum 3.26.0; exercise that executable version in CI. |
| GCC | Minimum 8.5, following PR 2190. |
| LLVM | Minimum LLVM/Clang development libraries 14, following PR 2190. |
| Language | Preserve the existing C++17 baseline; compiler and dependency ABI compatibility must still be checked. |
| Replacement | Fully replace obsolete framework CMake; no porting of its global flags, source copying, or old discovery modules. |
| Review | Each layer is usable and testable with its predecessors, without depending on a future repair PR. |
| Compatibility | Preserve required capabilities; prefer valid CMake-native behavior and document differences rather than demanding flag/output identity. |
| End users | Provide one command from a source checkout/release through build and installation, with useful prerequisite/error reporting. |
| Trick 27 | Deprecate Autotools while it remains usable. |
| Trick 29 | Remove Autoconf and the framework Make build. |

The GCC check applies to GNU compilers. AppleClang versions are not upstream
LLVM versions. Distinguish the host compiler, the LLVM library package, and
the simulation target compiler/ABI. RHEL 8.10 supplies CMake 3.26; earlier
RHEL 8 minor releases may need another package.
[RHEL release notes](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/8/html/8.10_release_notes/new-features)

## Migration boundary

CMake will build and install Trick's libraries, host ICG, embedded-Python
interface, native/Java tools, resources, and SDK metadata. Existing simulation
development through `trick-CP`, `S_define`, `S_overrides.mk`, and trickification
continues through a CMake-generated SDK configuration.

GNU Make may remain necessary for user simulations after Trick 29. It may
also be the backend generated by CMake. Removing Autoconf does not imply
removing either use of Make.

The initial platform scope follows documented Linux, macOS, and Windows via
WSL support, including the existing 32-bit Linux route. A native Windows/MSVC
port, generic cross-compilation support, new simulation definition language,
ICG rewrite, SWIG replacement, Perl removal, Python minimum bump, Java language
upgrade, and subsystem redesign are separate projects.

## Implementation rules

Use target-scoped requirements and explicit sources. Keep existing archive
boundaries as the initial model. Public includes, ABI definitions, and link
requirements belong to public interfaces; warnings and implementation-only
options do not. Export consistent `Trick::` build/install targets and a package
configuration. Do not use global include/link directories, global definitions,
source globs, or raw built-library paths when target references are available.
[Modern CMake guidance](https://cliutils.gitlab.io/modern-cmake/chapters/intro/dodonot.html)

- Configure-time work discovers dependencies and generates configuration.
  Compilation, ICG/SWIG execution, parser generation, and Java packaging belong
  in the build graph. Do not wrap the framework Makefile or Autoconf in CMake.
- Production generated files stay in the binary tree. Give every output one
  producer, complete input dependencies, and appropriate failure handling.
  Resolve ICG basename collisions before using a flat external output directory.
- Honor CMake's compiler/toolchain/generator selection. Keep LLVM package lookup
  separate from compiler selection and check matching LLVM/Clang installations.
- Preserve embedded Python initialization, static registration, symbol export,
  archive dependencies, and JIT/load behavior. SWIG's static Python-input archive
  must not accidentally become an ordinary extension module.
- Give core generated metadata an explicit output inventory. A manifest created
  at build time cannot alone add unknown source files to an existing build graph.
- Generate the compatibility SDK configuration from resolved build information.
  Installed simulations must not require the source/build trees or an Autoconf
  run. Do not recompute producer ABI/library layout from the consumer host.
- Install explicit artifacts with CMake-native layout and staging support.
  Source-relative resource readers need an installed location and a test.
- Add focused regression checks with each implementation PR. Do not defer all
  tests to final qualification or copy global fast-math/optimization flags without
  considering simulation correctness.

The artifact families in `inventory.json` describe baseline responsibilities;
they are not glob instructions or a final public target/export list. Each owning
PR must resolve its family into explicit sources/outputs/install entries.
Broad legacy directory-copy rules do not establish that every copied file is a
supported SDK artifact.

The `obsolete_framework_cmake` paths are historical references to the pinned A1
baseline: A2 replaces the root and deletes the other listed files. Do not require
deleted historical paths to exist in subsequent layers. The independent example
CMake files remain tracked.

## Source installer contract

Proposed command name: `./install-trick`. From an existing source checkout or
extracted release, one invocation checks prerequisites, configures, builds,
runs a small acceptance test, installs, and verifies the installed SDK by
building/running a scratch simulation. Users receive phase logs, meaningful
failure status, a feature summary, and the PATH setup command.

Prerequisite setup and source download are documented separately. The driver
does not silently install OS packages, elevate privileges, or modify shell
startup files. Developers keep normal CMake/CTest/IDE workflows. The driver
must not duplicate CMake's dependency resolution.

The launcher language, minimum interpreter, default prefix, generator fallback,
feature defaults, and options are proposals until the decisions below are
resolved. Implementation must remain compatible with supported source-install
platforms; do not silently impose Python 3.11 on RHEL 8 users.

## A1 acceptance and evidence

A1 is ready for review when its JSON parses, source-evidence paths exist at the
baseline, obsolete and independent CMake inventories account for all tracked
CMake build files, current configure options have a disposition, and relative
document links resolve. The diff must contain documentation only.

This layer records source inspection, not a claim that either build route
works on a given machine. Linux/macOS builds, installed simulations, and exact
tool/package versions are collected in the PR introducing the relevant behavior
and consolidated in F1. The environment template deliberately contains nulls
and `not-run`; never promote it to a verified result without actual execution.

## Branching

A1 is based on PR 2190's inspected head and lives on
`brendanny/trick:cmake/01-contract`. A native GitHub stack must keep all branches
within one repository. A fork PR into `nasa/trick` is not a native cross-fork
stack; use dependent PRs or arrange same-repository upstream branches when
landing the series. Rebase onto PR 2190's merged result before merging this
work independently.
